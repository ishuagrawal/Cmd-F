# Implementation decisions

The supplied engineering document is the product brief. Its agent-directed wording is not a separate authority. The user explicitly authorized implementation changes and renamed the product **Cmd-F**.

1. **Deliver a local preview first.** The API binds to `127.0.0.1`; random local client tokens are provisioned on the machine and compiled into the unpacked extension at build time. Hosted authentication, deployment quotas, and a network egress firewall are not supplied. The extension build rejects non-loopback API origins. Do not expose this backend as a shared hosted service.
2. **Keep the renderer out of the runnable system.** `ENABLE_RENDERER=true` fails closed. Building a renderer without OS/network isolation would not satisfy the brief. Its interface and exit gate are documented in `apps/renderer/README.md`.
3. **Use explicit consent for every search.** This is stricter and easier to audit than guessing which pages are private or persisting site-level consent. Revoke/clear deletes the current isolated search. An optional client-token override is the only persistent panel setting; the build already contains the provisioned token.
4. **Separate fixtures from production fetch policy.** `pnpm demo` adds fixed owned-origin fixture access alongside the normal public policy; test helpers can inject an isolated fixture policy. There is no environment variable, query parameter, or API field that makes the production fetcher accept loopback. The browser suite copies the real build and adds only the owned fixture host permission for automation.
5. **One public page fetch at a time.** This is below the proposed maximum concurrency and simplifies cancellation and per-origin pacing. No distributed queue, vector service, or agent framework is introduced.
6. **Use bounded block extraction with a section catalog.** Paragraphs, lists, tables, and code stay as real blocks rather than always being regrouped to exactly 100–250 words. Blocks above 9,000 characters are individually marked as truncated and cannot produce direct evidence; an unrelated long block does not invalidate other passages. The extractor has a 16,000-element / 500 ms bound; selected payloads have an 80 KB server limit. Generic sentence-level quote narrowing is deferred to avoid losing qualifications.
7. **Use local node identity and hash validation for highlighting.** Stable live targets are supported, including duplicate text under different headings. Exact quote relocation in newly opened source tabs is deferred. Source navigation uses validated URLs with heading anchors and always requires a user click. No optional cross-origin permission flow is included.
8. **Keep scope to one exact origin.** Related documentation/help origins may appear in the page, but are not crawled or automatically approved. An additional-origin approval workflow and advertised `llms.txt`/documentation-index adapters are future work.
9. **Conservative provider payload ceilings.** The adapter checks serialized bytes for the documented overall and state-plus-largest-question budgets; it does not claim an exact provider tokenizer. Requests below the local byte ceilings can still fail upstream validation, which ends the search with a verification error. Context/token handling needs verification with a live account.
10. **Cache anonymous public artifacts only.** SQLite honors private/no-store/no-cache, cookies, authentication headers, varying responses, and expiry ceilings. Conditional validator requests and cache observability dashboards are deferred.
11. **Keep mock semantics visible.** The mock uses deterministic keyword overlap; it has no hidden generative model. UI says “Demo provider” / “Demo match.” Live outages stop verification and report a specific failure; keyword fallbacks and partial candidates are not displayed. The mock’s synthetic support values are routing inputs, never correctness percentages.
12. **No production acceptance claim.** Source/build/unit/browser verification is distinct from live Jev quality, manual Chrome toolbar/side-panel behavior, arbitrary real-site coverage, store review, and hosted isolation. Remaining gates are listed in the evaluation report.
